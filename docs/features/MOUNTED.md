# Mounted APFS and ExaCopy

`apfs-mounted` supplies macOS filesystem operations over caller-authorized descriptors. The image crates retain their `no_std` build profiles. ExaCopy selects its admitted transfer profile and owns authorization, job layout, the copy state machine, BLAKE3 verification, signed ownership, journal and receipt formats, intent ordering, conflict decisions, and recovery policy. [Package usage](../../crates/platform/apfs-mounted/README.md)

| Capability | Library coverage and integration gap |
| --- | --- |
| Volume capabilities | `volume::observe_mount` supplies typed locality and mount ownership behavior for live checks. `volume::observe` also queries independent capability results for permissions, ownership, ACLs, advisory locks, and exclusive rename. Invalid or unavailable capability bits produce `Unknown`. [Volume API](../../crates/platform/apfs-mounted/src/volume.rs) |
| Object identity | `ObjectIdentity` captures device, real FSID, nonzero inode, optional generation, and birth time from a held object or single no-follow name. `EventEntry::with_observation` combines identity, extent, change time and bounded metadata, with held and named state checked around the query. Private entries can require exact stored spelling, and public occupancy can use ordinary lookup spelling. [Identity API](../../crates/platform/apfs-mounted/src/identity.rs) [Coherent observation](../../crates/platform/apfs-mounted/src/publication/observation.rs) |
| Scoped namespace | `EntryName` preserves one validated raw component. `Directory` supports descriptor-relative no-follow opens, stored spelling, event handles, and private directory creation. `PrivateWriter::create` exclusively creates files. [Scope API](../../crates/platform/apfs-mounted/src/scope.rs) |
| Advisory leases | `Lease` provides nonblocking shared and exclusive acquisition, busy results, revalidation, and process-aware release. The lease coordinates cooperating writers. [Lease API](../../crates/platform/apfs-mounted/src/lease.rs) |
| Dataless handling | `with_materialization_disabled` sets and verifies the calling thread's policy, verifies normal restoration, attempts restoration during unwinding, and retains the callback result on restoration failure. Genuine dataless files still need native qualification. [Policy API](../../crates/platform/apfs-mounted/src/dataless.rs) |
| Pinned reads | `PinnedSource::open_leased` lets the caller check named identity and metadata before a data open. The pinned source borrows the selected lease, checks the name and held identity before and after I/O, and probes EOF on the same descriptor. [Source API](../../crates/platform/apfs-mounted/src/source/admission.rs) |
| Metadata observation | `ObjectFlags` interprets firmlink, dataless, and compression flags and preserves all native bits. Scoped `MetadataView` queries ACLs, forks, xattrs and stat through the pinned source or stage. Xattr visibility is explicit and the caller bounds the inventory. ExaCopy's strict profile rejects visible xattrs, including `com.apple.provenance`. [Metadata API](../../crates/platform/apfs-mounted/src/metadata.rs) |
| Metadata application | `ClosedFile::apply_times_checked` runs caller checks on the same held descriptor before timestamps change, after they change, and after the full-file barrier. `BirthTimePolicy::Preserve` refuses a birth-time change and retains the private entry. `ClosedFile::seal_checked` preserves existing timestamps and checks the same read-only descriptor on both sides of the full-file barrier. Rich metadata reproduction remains open. [Writer API](../../crates/platform/apfs-mounted/src/writer.rs) · [Sealing API](../../crates/platform/apfs-mounted/src/writer/seal.rs) |
| Private file lifecycle | `PrivateWriter::create_with_initial_flags` can require zero initial flags. The writer bounds writes, retires after failures, and reports synchronization and checked-close evidence. `ClosedFile` independently reopens the same inode for bounded read-back and EOF revalidation. Failed verification after creation is reported separately and retains the stage. [Writer API](../../crates/platform/apfs-mounted/src/writer.rs) |
| Durability | `full_file_sync` and `sync_directory` expose Darwin `F_FULLFSYNC` and directory synchronization. `sync_directories` reports the two outcomes individually. ExaCopy's live journal still calls `rustix` directly. Power-loss recovery remains unqualified. [Barrier API](../../crates/platform/apfs-mounted/src/writer/barrier.rs) |
| Publication | After durable intent, `attempt_exclusive_rename` revalidates the held and named source and asks Darwin for one exclusive no-follow rename without a destination prelookup. It distinguishes pre-call refusal, incumbent conflict, uncertain effect, and kernel success. After success, attempt both directory barriers and use `RenamedEntry::with_observation` for held identity, fresh change time, extent and bounded metadata with former-name and destination revalidation. `RenamedEntry::observe` still exposes separate namespace evidence for reconciliation. Receipt promotions can use one barrier. [Publication API](../../crates/platform/apfs-mounted/src/publication.rs) [Coherent observation](../../crates/platform/apfs-mounted/src/publication/observation.rs) |
| Recovery | `inventory` and `pin_entry` provide present, absent, or inconclusive name evidence without public payload reads. `ReopenedStage::open` borrows a fresh event anchor. `ReopenedStage::open_named` takes ownership of a validated component and opens and holds its own event anchor, so a caller can return the reader from its open method. Both constructors borrow the matching lease, check exact spelling and expected extent, and run caller identity and ACL admission before opening the data descriptor. Bounded exact reads, EOF checks and metadata queries retain that binding. `with_observation` samples identity, extent, change time and bounded metadata together through the pinned read-only descriptor. [Inventory API](../../crates/platform/apfs-mounted/src/publication.rs) [Recovery API](../../crates/platform/apfs-mounted/src/recovery.rs) |

ExaCopy's current pin already consumes the companion's leased source, private writer, and exclusive rename APIs. Its restart path still uses its existing adapter. When adopting the recovery reader, compare all recorded identity fields during admission and continue checking protected ancestry, public-name occupancy, strict metadata and signed evidence in ExaCopy. Query the read-only descriptor with `with_metadata` before and after reads when the caller needs live timestamps. Opening the reader also exposes pre-open timestamps. The existing managed profile admits APFS. Pomologie's HFS+ crates remain image-oriented. The installer resource-fork refusal is a generic Darwin policy in ExaCopy.

The checked rename variant, `attempt_exclusive_rename_checked`, calls the grant callback after held and named identity validation. It retains the returned guard through the exclusive no-follow syscall. A callback error prevents the syscall, and native preflight refusal, conflict, uncertain effect and success retain their existing representations. ExaCopy owns the grant, deadline, lease and durable intent. The callback is the last point to check the deadline before submission. [Checked rename](../../crates/platform/apfs-mounted/src/publication.rs)

`OwnedEventEntry::open_named` lets a recovery inventory keep the validated raw name and event descriptor together with a duplicate of the held directory descriptor. Initial absence returns `None`. A failed open or a changed binding returns an error. Call `with_observation` with `EntrySpelling::Exact` for private names and `EntrySpelling::Lookup` for public occupancy. ExaCopy still checks its protected ancestry, lease, and the relationship between observations of the private and public names. [Publication API](../../crates/platform/apfs-mounted/src/publication.rs)

`write_private_artifact_checked` exclusively creates a named private file, writes the caller's byte slice, performs the full-file barrier and checked close, then independently reopens the same inode to compare exact bytes and check EOF. The caller may fence creation with a guard and check metadata before writing, before the barrier, before the read-only open, and around read-back. Failures identify the lifecycle phase and retain the underlying native or policy error. Once created, the name is retained for reconciliation. ExaCopy owns artifact names, framing and size limits, protected ancestry, lease admission, namespace barriers and any promotion of a pending name. [Writer API](../../crates/platform/apfs-mounted/src/writer/artifact.rs)

The macOS tests exercise mutation-free sealing with an actual file barrier, leased owned recovery opens with bounded reads and an EOF probe, and coherent event and post-rename observations. They reject changed permissions, rebinding, and a former name recreated during observation. The publication test attempts both directory barriers before collecting post-rename evidence. Genuine dataless files, cross-volume substitution, process-crash recovery and power-loss durability still need separate qualification. [Writer tests](../../crates/platform/apfs-mounted/src/writer/tests.rs) [Recovery tests](../../crates/platform/apfs-mounted/tests/private_recovery.rs) [Publication tests](../../crates/platform/apfs-mounted/tests/private_publication.rs)

The portable reader covers documented profiles for xattrs, resource forks, FinderInfo, hard links, sparse files, and name matching. Shared and cloned extents, compression, snapshots, encryption, and broader consistency checks remain open. Snapshot support would give a future ExaCopy transfer profile an identified immutable source view. [Portable reader profiles](READ.md)
