# Mounted APFS and ExaCopy

`apfs-mounted` supplies macOS filesystem operations over caller-authorized descriptors. The image crates retain their `no_std` build profiles. ExaCopy selects its admitted transfer profile and owns authorization, job layout, the copy state machine, BLAKE3 verification, signed ownership, journal and receipt formats, intent ordering, conflict decisions, and recovery policy. [Package usage](../../crates/platform/apfs-mounted/README.md)

| Capability | Library coverage and integration gap |
| --- | --- |
| Volume capabilities | `volume::observe` reports filesystem type, locality, mount flags, and independent capability results for permissions, ownership, ACLs, advisory locks, and exclusive rename. Invalid or unavailable capability bits produce `Unknown`. [Volume API](../../crates/platform/apfs-mounted/src/volume.rs) |
| Object identity | `ObjectIdentity` captures device, real FSID, nonzero inode, optional generation, and birth time from a held object or single no-follow name. Revalidation compares the authorized parent, name, and live object. `metadata::stat` supplies additional facts. [Identity API](../../crates/platform/apfs-mounted/src/identity.rs) |
| Scoped namespace | `EntryName` preserves one validated raw component. `Directory` supports descriptor-relative no-follow opens, stored spelling, event handles, and private directory creation. `PrivateWriter::create` exclusively creates files. [Scope API](../../crates/platform/apfs-mounted/src/scope.rs) |
| Advisory leases | `Lease` provides nonblocking shared and exclusive acquisition, busy results, revalidation, and process-aware release. The lease coordinates cooperating writers. [Lease API](../../crates/platform/apfs-mounted/src/lease.rs) |
| Dataless handling | `with_materialization_disabled` sets and verifies the calling thread's policy, verifies normal restoration, attempts restoration during unwinding, and retains the callback result on restoration failure. Genuine dataless files still need native qualification. [Policy API](../../crates/platform/apfs-mounted/src/dataless.rs) |
| Pinned reads | `PinnedSource` performs bounded positioned reads with exact completion, checks the selected name and held identity, and explicitly probes EOF during final revalidation. It describes a live file. The ExaCopy adapter still needs a way to query the complete metadata inventory on the same pinned object. [Source API](../../crates/platform/apfs-mounted/src/source.rs) |
| Metadata observation | The metadata API provides owner, permissions, links, flags, times, ACL and security GUID evidence, xattr names and values, FinderInfo, and resource forks. Xattr visibility is explicit and the entire inventory has a caller-supplied bound. ExaCopy's strict profile rejects visible xattrs, including the observed `com.apple.provenance`. [Metadata API](../../crates/platform/apfs-mounted/src/metadata.rs) |
| Metadata application | The library applies and confirms access and modification times and supports explicit empty ACL provisioning after private directory creation verifies the mode. Rich xattr, fork, ACL, ownership, and flag reproduction remain open. [Metadata API](../../crates/platform/apfs-mounted/src/metadata.rs) |
| Private file lifecycle | `PrivateWriter` exclusively creates and owns the writer, performs bounded writes, issues a full-file barrier, and reports checked close. `ClosedFile` independently reopens the same inode for bounded read-back and EOF revalidation. [Writer API](../../crates/platform/apfs-mounted/src/writer.rs) |
| Durability | `full_file_sync` and `sync_directory` expose Darwin `F_FULLFSYNC` and directory synchronization. `sync_directories` reports the two outcomes individually. ExaCopy's live journal still calls `rustix` directly. Power-loss recovery remains unqualified. [Barrier API](../../crates/platform/apfs-mounted/src/writer/barrier.rs) |
| Publication | `exclusive_rename` distinguishes conflict, uncertain effect, confirmed rename, and incomplete post-rename evidence. It revalidates the namespace against the expected held inode. [Publication API](../../crates/platform/apfs-mounted/src/publication.rs) |
| Recovery | `inventory` and `pin_entry` provide present, absent, or inconclusive name evidence without public payload reads. Callers can reopen and read a private file under a fresh authorized directory. The `ClosedFile` read-back path requires a live writer result. A restart-specific API binding the reopened stage to expected identity, length, EOF, and metadata remains open. [Inventory API](../../crates/platform/apfs-mounted/src/publication.rs) [Read-back API](../../crates/platform/apfs-mounted/src/writer/read_back.rs) |

The macOS integration test exercises pinned reads, a leased private stage, checked close, independent read-back, timestamp application, exclusive publication, and both directory barriers. A disposable ExaCopy checkout exercised identity, volume, and thread-policy adapters. Its strict copy fixture stopped during xattr admission. The live ExaCopy workspace has yet to adopt the companion, and native cross-volume substitution remains unqualified. [Publication test](../../crates/platform/apfs-mounted/tests/private_publication.rs) [ExaCopy qualification](../../crates/platform/apfs-mounted/README.md#exacopy-integration)

The portable reader covers documented profiles for xattrs, resource forks, FinderInfo, hard links, sparse files, and name matching. Shared and cloned extents, compression, snapshots, encryption, and broader consistency checks remain open. Snapshot support would give a future ExaCopy transfer profile an identified immutable source view. [Portable reader profiles](READ.md)
