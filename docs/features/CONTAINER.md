# APFS containers, checkpoints and object maps (A-CONT-01 through A-CONT-04)

Source baseline S12, especially container and object map sections; qualify exact field tables against real fixtures. Design ledger records each field offset/size/endian/signedness, version/flags, source, validation and test IDs. APFS objects are little-endian in documented profile, use checked offsets, no native struct cast. Separate physical block address, virtual object ID, ephemeral object ID, transaction ID (XID), container block size, byte offsets. Container may have multiple volumes and storage tiers; initial read only unencrypted single physical store with supported flags. Reject unsupported required feature flags, unknown storage addressing, unsupported descriptor trees or tiers explicitly. Recognize outer container metadata even when volume content unsupported, if bounds safe. Block size/count and partition length validated before any multiplication/allocations, object header type/subtype/flags/version/OID/XID/checksum verified against expected context. Object checksum qualification uses APFS specified checksum algorithm (Fletcher-64 variant), object size/range and exact coverage from fixtures; no universal per-file checksum claim.

## Checkpoint selection

Use `apfs_container::probe_extent` to recognize a partitionless container through a bounded `ReadAt` source. A short prefix or missing NXSB magic means absence. A recognized malformed block or failed source read returns a typed error. A successful result bounds the declared container within the source, including when the source has trailing bytes. The probe reads only block zero and leaves checkpoint and volume admission to subsequent operations. [Extent probe tests](../../crates/container/apfs-container/tests/probe_extent.rs)

For A-CONT-01-T01, the Sonoma 14.7.2 fixture comes from a native 64 MiB data container created from a synthetic file tree. Apple’s offline checker selected XID 4, and the ledger records the unmodified bootstrap block, its checksum and source provenance. The retained blocks reproduce the same selected transaction. With input changes, an invalid block size stops after the prefix. An invalid count, wrong object type or incorrect checksum stops after one bounded bootstrap block with a typed error. An unknown required feature bit returns an explicit unsupported profile for block zero and transaction 4. None of these cases reaches checkpoint traversal or allocation sized by the unvalidated geometry. [Native bootstrap tests](../../crates/filesystem/apfs-reader/tests/view/bootstrap.rs) · [Fixture and checksum ledger](../../crates/filesystem/apfs-reader/tests/fixtures/sonoma-populated-fsroot.json)

The bootstrap fuzz target uses the same native block in two modes, with the stored checksum left in place or recomputed to exercise geometry checks on complete inputs. It checks that bootstrap reads stay within block zero and that any admitted extent equals the declared size computed with widened arithmetic within the source. The `check-bootstrap.sh` runner completed 20,000 inputs with seed 7 and AddressSanitizer on arm64 macOS with cargo-fuzz 0.13.2 and `nightly-2026-11-04`. This run assesses extent probing. The typed checkpoint-opening results come from the native-derived tests above. [Fuzz harness](../../crates/container/apfs-container/verification/fuzz/fuzz_targets/bootstrap.rs) · [Fuzz runner](../../crates/container/apfs-container/verification/fuzz/check-bootstrap.sh)

Block-zero container superblock provides geometry and checkpoint descriptor/data location; do not assume block zero is newest. Enumerate supported descriptor ring with wrap-safe indexes and bounds. Validate candidate superblocks and associated checkpoint map records, group by XID, ensure expected descriptor/data ranges, no duplicate ambiguous OIDs or cross-checkpoint mix. Select highest complete valid committed candidate within qualified profile, not merely largest XID; a malformed latest checkpoint may fall back to an older valid one with explicit diagnostic and selected XID. Do not mask unsupported required feature or corruption as an ordinary clean latest state. Distinguish ordinary fallback permitted by format evidence from unsafe unsupported checkpoint. Validate ephemeral object mapping, object types/size and checksums, physical object lookup by bounded block address. Track immutable view identity and provenance; no repair, no writes, no checkpoint rewriting. Unsupported descriptor-tree layouts explicitly unsupported until tested; do not scan entire disk for magic. Test ring wrap, torn latest, malformed map, mismatched XIDs, missing object, duplicate, overflow, unknown flags, truncated/multi-store/fusion, older valid fallback, no valid checkpoint.

Use `Container::open_at` to open a retained checkpoint by transaction ID. It scans the bounded descriptor ring to verify uniqueness, then validates the matching descriptor, its checkpoint maps and required objects. A matching XID is necessary for success. An absent XID returns `CheckpointNotFound` with any descriptor damage found during the scan. A checksum failure leaves the damaged descriptor's XID unknown. A checksummed matching descriptor can return a corruption, unsupported-profile, or ambiguity error. The selected checkpoint provides the geometry and object map for subsequent volume reads. Snapshot selection has its own metadata and remains a separate capability.

The Sonoma 14.7.2 fixture contains native checkpoint and object-map blocks at XIDs 1 and 2. The exact-selection tests check both views, including the volume that becomes visible in the later map. Mutations check torn targets, absent IDs, ambiguous descriptors, unsupported flags, source failure and read limits. This adds coverage to A-CONT-02-T01 through A-CONT-02-T03 and A-CONT-03-T01. [Exact selection tests](../../crates/container/apfs-container/tests/checkpoint_selection/exact.rs) · [Native fixture ledger](../../crates/container/apfs-container/tests/fixtures/native-apfs.json)

The wrapped-descriptor test uses those two native checkpoints as the base for a controlled synthetic ring. It establishes that XID 2 is selected while its map is present. With its map slot blank and its NXSB checksum still valid, exact selection reports candidate corruption and automatic selection returns XID 1 with both rejection and fallback diagnostics. With both map slots blank, automatic selection returns `NoCheckpoint` and retains both rejected candidate identities. A bounded reference model compares selection and diagnostics across 147 wrapped-ring cases. [Checkpoint tests](../../crates/container/apfs-container/tests/checkpoints.rs) · [A-V02 evidence](../../crates/container/apfs-container/verification/README.md#a-v02-checkpoint-selection)

## Object maps and B-trees

Virtual objects resolve via container or volume-specific object map appropriate to namespace. Map search uses `(OID,XID)` ordering and greatest mapping XID <= requested view XID for same OID (including deletion/tombstone/flags semantics). Never use mapping from newer transaction; verify key/value sizes, mapping flags, physical address, object type and expected ID/XID context. Distinguish ephemeral from virtual and physical; no use of virtual ID as physical address. Cache keyed by container identity+view XID+object namespace+OID, not just OID. Check recursion and reference loops, capped reads. APFS B-tree node types/layout: fixed/variable key-value records, table of contents, free-space regions, flags/root footer/tree info, node level, leaf/index forms, physical vs virtual child pointers, per-tree comparator, sorted keys, range/height consistency, checksums. Validate every slot and data region, no aliasing overlapping key/value storage except evidence-qualified structure, bounded depth and visited node IDs. Separate object-map and filesystem-tree typed codecs. No reusing HFS+ B-tree format or generic lexicographic compare. Use iterators and lazy read, no whole-container scan for normal open.

A-CONT-01-T03 exercises one numeric identity in three addressing contexts within a single selected checkpoint. The synthetic fixture places the physical object map at that block address, leaves the ephemeral free queue in its checkpoint data slot, and maps a virtual volume to a third block. The three references resolve independently. Substituting checksummed objects with the same OID and XID across those contexts produces typed failures. This establishes namespace separation for the tested paths. Virtual and ephemeral IDs share the wire-level `ObjectId` type and are distinguished by their lookup context. The fixture does not qualify native consistency, arbitrary physical object lookup, or free-queue contents. [Namespace tests](../../crates/container/apfs-container/tests/checkpoint_selection/namespaces.rs)

### Implemented container-map profile

The container map is manually managed and uses checksummed physical nodes with fixed-size aligned records. Headerless, hashed and variable-record nodes, flagged mappings other than ordinary tombstones, and snapshot or pending-revert maps are outside this profile. Lookup validates the map, occupied slots and bounded key/value free lists in each node along one path. It verifies child bounds, levels and transaction lineage on that path. Object reads verify the selected mapping's complete payload header against the expected virtual type, OID and mapping XID. An earlier XID filters the current container-map keys and does not establish an older checkpoint or snapshot view.

The [native fixture ledger](../../crates/container/apfs-container/tests/fixtures/native-apfs.json) records root-leaf maps at XIDs 1 and 2 and the volume object with the UUID reported by Apple’s read-only checker. Synthetic two-level trees exercise key routing and tombstones across leaf boundaries, and mutations exercise layout, identity, range and budget failures. Native multi-level and historical-version fixtures and A-V03/A-V04 formal gates remain open. The wire codec follows the object-map and B-tree sections of [Apple File System Reference](https://developer.apple.com/support/downloads/Apple-File-System-Reference.pdf).

| --- | --- | --- |
| Standard object header | Unsigned little-endian checksum, OID and XID at 0, 8, 16 (8 bytes each), type and subtype at 24, 28 (4 bytes each) | Fletcher-64 over the bytes after the checksum. Physical map/node OID equals its block address. A virtual read checks the mapping's OID and XID, the caller's expected subtype and the full virtual type word. Native and wrong-namespace checks in A-CONT-03-T01. |
| Map header | Unsigned little-endian flags, snapshot count, mapping tree type and snapshot tree type at 32, 36, 40, 44 (4 bytes each), root pointer at 48 (8 bytes). Snapshot pointer and three XIDs at 56, 64, 72, 80 (8 bytes each). | Manually managed flags and physical tree. The root names one positive bounded physical block. Snapshot count, pointer, snapshot XID and pending-revert fields are zero. Native map and unknown-flag checks in A-CONT-03-T01. |
| Node metadata | Unsigned little-endian flags and level at 32, 34 (2 bytes each), record count at 36 (4 bytes), then table/free-space and key/value free-list locations at 40, 44, 48, 52 (2-byte offset and length each) | Table offset relative to byte 56 and shared free space relative to the end of the table. All occupied slots are bounded and disjoint. Root/leaf/fixed flags depend on type and level. Free-list links count forward from the key region start or backward from the value region end. Aligned free spans must stay inside their region, agree with the declared combined length, and never overlap a record or another span. Offset `0xffff` terminates the list. | Fixed record | 4-byte TOC slot containing two unsigned 2-byte little-endian offsets. The key is unsigned 8-byte OID then 8-byte XID. The value is an 8-byte child OID, or unsigned 4-byte flags, unsigned 4-byte byte count and signed 8-byte physical address. | Key offset counts forward from the key area and value offset backward from its end. Child OIDs identify physical blocks. Numeric `(OID,XID)` order; no overlapping slots, nonpositive addresses, invalid sizes or future entries. A visible tombstone does not use the address and size fields. A-CONT-03-T01 and A-CONT-04-T01 subsets. |
| Root footer | Final 40 bytes. Unsigned little-endian flags, node size, key size, leaf value size, longest key and longest value (4 bytes each), then total keys and nodes (8 bytes each). | Physical tree with optional sequential-insert hint, container-sized nodes, 16-byte keys and leaf values. The footer is outside the node's record area. Exact leaf-root counts are cross-checked. Native and synthetic profile from A-CONT-04-T01. |

## Volumes and container services

Enumerate filesystem object IDs from selected NXSB, resolve actual volume superblocks, validate volume identity, OID namespace, features, role, quota/reserve, object map/root tree/snapshot/extent refs and associated XID. Preserve unknown features in inspection report but reject unsupported required behavior. Multi-volume enumeration read-only supported after fixtures; explicit volume selection (no first-nonempty). Inspect space manager, reaper, free queues, object maps and refs in separate typed views; reader need not mutate, but builder/checker will require their full accounting. Free space is shared at container level, not independent sum per volume; don't fabricate totals. Normal data volume only for fresh constructor; system roles, volume groups, sealed/fusion/keybag support separately qualified. Snapshot view must bind to proper snapshot metadata/tree root and object map XID; no reading newest mappings for old snapshot. Add snapshot read later with multiple levels, not one leaf assumed. Object checksums, feature bits and consistency diagnostics visible, not authenticity. Native `fsck_apfs` independent verification on disposable test containers only.

### Implemented APSB metadata profile

`Container::volumes` validates the selected NXSB volume table before reading objects, then resolves all declared volumes in slot order under one aggregate I/O budget. `Container::volume` selects a specific OID. Both query the object map at the selected checkpoint XID. Copy-on-write objects from earlier transactions remain visible when their mapping ID and XID match the verified APSB. Each APSB slot index must agree with its NXSB slot, including gaps in the table. Before opening trees, callers can use the checkpoint-local volume selector by OID or UUID, or request the single checked volume. Implicit and UUID selection require a complete admitted volume list. An explicit OID checks the table and lets the caller open just that volume. [Selection regressions](../../crates/container/apfs-container/tests/volumes/discovery.rs)

The codec admits ordinary unencrypted volumes with no role or an ungrouped data role. It preserves optional and read-only-compatible masks and admits the required case and normalization comparison bits as metadata. Encrypted or grouped volumes, sealed metadata, snapshot and revert states, other roles, and unknown incompatible features return explicit errors. Tree declarations are checked for expected namespaces, bounds, and known reserved or aliased locations. Their contents and allocation accounting require separate traversal.

| Region | Byte layout | Admission and evidence |
| --- | --- | --- |
| NXSB table | Unsigned little-endian maximum count at 180 (4 bytes) and up to 100 virtual OIDs at 184 (8 bytes each). | Occupied slots must be below the maximum. OIDs must be distinct and allocated in the virtual namespace. Native and synthetic sparse-slot fixtures exercise A-CONT-04-T01. |
| APSB identity | Standard object header and `APSB` at 32 (4 bytes), unsigned little-endian slot index at 36 (4 bytes), UUID at 240 (16 wire bytes), UTF-8 name at 704 (256 bytes), role at 964 (2 bytes). | One complete checksummed virtual object, matching OID/XID and slot, nonzero UUID, NUL-terminated name, supported role. Enumeration rejects duplicate UUIDs. FSCK name and UUID match the fixture. |
| Feature masks | Unsigned little-endian optional, read-only-compatible, incompatible and status masks at 40, 48, 56 and 264 (8 bytes each). | Preserve masks. Status must be unencrypted with only qualified flags. Unsupported incompatible flags and special roles are rejected before exposing a volume. |
| Block declarations | Unsigned little-endian reserve, quota and allocation at 72, 80, 88 (8 bytes each). | Quota, reserve and allocation fit the container and any nonzero quota. These are individual declarations. |
| Tree declarations | Unsigned little-endian root, extent-reference, and snapshot-metadata types at 116, 120, 124 (4 bytes each), and map, root, extent-reference and snapshot-metadata OIDs at 128, 136, 144, 152 (8 bytes each). | Filesystem root is a separate allocated virtual OID. The map, extent references and snapshot metadata are physical in the admitted profile. Physical references must fit the container outside checkpoint rings. |
| Unsupported state fields | Unsigned little-endian revert XID, revert superblock, snapshot count, root-to XID, encryption-roll OID, snapshot extension OID, integrity OID and file-extent OID at 160, 168, 216, 968, 976, 1000, 1024, 1032 (8 bytes each), and volume-group UUID at 1008 (16 bytes). | Require zero for the ordinary no-snapshot profile. ### Implemented volume-map profile

`Container::open_volume_objects` resolves the selected volume through its NXSB slot and checks the physical map declared by the verified APSB. Ordinary unencrypted volume maps use zero map flags and the same checked physical B-tree node layout as container maps. The map header must agree with the declared address and be at least as old as its referencing APSB. Subsequent queries use the selected checkpoint XID and the volume map exclusively. One read budget covers opening the volume, reading its map, and looking up or reading each object through the opened view.

The native ordinary volume at XID 2 uses map block 193 and a single root-leaf at block 194. The filesystem root at virtual OID 1028 maps to block 197. The lookup tests verify the mapping and complete virtual object header, isolation from the container namespace, the shared read budget, tombstones, and rejected map ownership or physical aliasing. Apple’s offline read-only checker passed the volume object map and filesystem root on the exact source image. [Fixture ledger and expected block identities](../../crates/container/apfs-container/tests/fixtures/native-apfs.json)

The volume node at block 207 resolves filesystem root OID 1028 at XID 3 to block 205. Both native nodes contain one 16-byte hole in each region.
