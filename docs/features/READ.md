# APFS file and metadata reader (A-READ-01 through A-READ-04)

Use selected immutable container checkpoint and volume view, with APFS-specific record key parsing and name semantics (not HFS+ Unicode tables). Source S12 and version-qualified native fixtures. Traverse filesystem root B-tree; parse record kind and object identity, inode, directory records, siblings/hard link records, extents, data streams, xattrs, extended fields, timestamps, permissions, flags, link counts, directory counts and optional sparse/compressed metadata. Validate variable-length names and extended fields, record lengths, alignment, per-record ordering and hash/name lookup behavior, use actual volume case/normalization/hash flags. Distinguish display names from raw encoded names; reject invalid semantics, not lossy normalize. Test case-sensitive and case-insensitive variants, Unicode composed/decomposed, supplementary code points, same hash collisions, forbidden names and maximum lengths from evidence. Directory records map names to file IDs, link siblings require verified semantics; handle hard links without conflating link entry and inode. Bounded traversal, parent references and symlink target bytes; explicit in-volume symlink resolution only, no host lookups, no loops. Unknown inode/xfield features that affect read semantics fail for affected files, preserve raw metadata in inspector. Never return zero data for unhandled object.

## Data and xattrs

Map file logical byte range to validated file extent records, data stream identity, physical blocks, sizes and offsets; use checked geometry, sparse holes only when format specifies them, not on missing extent. Shared extents/clones may legally overlap with correct reference accounting; reader does not allocate/copy-on-write. Validate bounds, read exact data bytes; regular file length distinct from allocated/physical bytes; no universal file checksum. Verify typed inline xattrs vs external/data-stream-backed attrs, resource fork and Finder metadata mapping; preserve ACL/security attrs where representable, raw and decoded representations distinct. Compression support explicit decmpfs type ledger (inline and resource-fork framing, zlib, LZVN, LZFSE, others only after fixture qualification). Validate declared logical length, decoder consumption and caps; unknown type or encryption requires typed unsupported, never empty fallback. Resource forks/xattrs can be large, stream within budget. Timestamp precision and epoch per field; explicit conversions; no host locale. Encryption detection must block plaintext interpretation, sealed volume integrity not automatically verified. Keybags/Fusion require separate gated modules. Read-only encrypted metadata only if safe/evidenced, never brute force or bypass.

### Implemented regular-file hard links

`VolumeView::hard_links` checks the recorded sibling group against the inode’s link count and primary parent. Each sibling record must match its inverse map and its parent’s exact directory entry. Sibling IDs are exposed separately from the shared inode number. Normal stored-name lookup verifies the chosen entry’s sibling and map before exposing its target. The group must fit the configured entry limit and all scans share the volume’s aggregate read budget. [Apple File System Reference, Siblings](https://developer.apple.com/support/downloads/Apple-File-System-Reference.pdf#page=115)

The A-READ-01 fixture contains three names for one ordinary inode and a separate resource stream. Apple’s checker passed at XID 4. On the read-only native mount, all three names reported inode 17 and link count 3, and both forks matched the synthetic input bytes. Reader tests reproduce the native identities and payloads, and reject changed link counts, mismatched names, and an inverse map pointing to another inode. Clones, sparse data, and non-regular hard links remain separate profiles. [Fixture ledger](../../crates/filesystem/apfs-reader/tests/fixtures/sonoma-hard-link-blocks.json)

## Snapshot and inspection capabilities

Volume handle tied to checkpoint/view XID. Support snapshot enumeration and selected snapshot reads only after validating snapshot metadata/name trees, snapshot superblock and root/object-map context, reference accounting and recursive tree depth. Multi-volume views use UUID/OID, actual volume roles and feature flags. `inspect` exposes container/volume metadata, physical allocation info where supported, object types/checksums/XID and map details, file record fields and raw bytes bounded, extents/shared storage indicators (label inferred vs known), snapshot list, unknown flags. Report unsupported capabilities explicitly. `check` validates qualified structure: complete checkpoint, object mappings/checksums, root and directory/inode/extents/attrs consistency, supported ref accounting and space-manager state, full data traversal when requested; unknown invariants prevent all-clear. Read-only check no repair. Metadata-only inspect avoids full payload. Cache by view identity; request budgets and cancellation at every object/tree boundary. CLI raw-container inspection, ls/stat/cat/check; no kernel mounts needed.

### Implemented reachable structural check

`VolumeView::check_reachable` checks a selected checkpoint's root-reachable directory records, inode identities and types, hard-link counts and reverse mappings, inline symbolic links, xattr storage, resource-fork flags, and unshared extent ownership. It checks for repeated data-stream IDs and physical overlap between the reached payloads. Metadata mode reads the referenced metadata. Data mode also reads every logical byte of each distinct regular inode and each xattr within an explicit byte limit. Aggregate record, depth, and extent limits supplement the view's tree and source budgets. Cancellation is polled between directory records, queries, and payload reads. The operation covers reachable reader profiles. Spaceman, unreachable records, snapshots, name equivalence, whole-tree diagnostics, and CLI integration remain separate work.

Hosted tests use the native empty and hard-link fixture blocks. The latter verifies one inode reached through three different names, its regular data and resource fork, and a structural overlap between the two forks that their individual ownership checks cannot detect. Independent native `fsck_apfs -n` and full-image reader runs cover empty, populated, split-tree, payload, attributes, fragmented, and hard-link images. This contributes evidence to A-READ-02-T01 and A-READ-04-T01 for the admitted reachable profiles. ## Tests

Read native unencrypted regular data volumes including empty/large trees, multi-volume and case sensitivity modes, fragmented and sparse data, regular hard links, symbolic links, resource forks, inline and stream xattrs, timestamp precision, compressed files by admitted type, clones and snapshot view divergence, native checkpoint wrap/fallback. Independent reference readers only for supported overlap. Native mount/stat/readlink/xattr/bytes oracle, fsck. Negative: wrong OID/XID/type/checksum, unknown required flags, missing/deleted mapping, bad TOC, unsupported encrypted/sealed/Fusion, truncated extents, huge logical sizes, malformed xfields, cycle, aliasing records, snapshot selecting newer data. Fuzz all parsers and verify read budget. No verified support claims without per-profile evidence.
