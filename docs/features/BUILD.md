# APFS fresh-image constructor (A-BUILD-01 through A-BUILD-03, optional later)

Fresh deterministic ordinary data-volume construction is not general-purpose APFS mutation. Gate it on qualified reader, checkpoint/object-map invariants and explicit evidence for allocator/free queues and volume metadata. Initial write profile: single unencrypted physical store, one regular data volume, supported case-sensitivity setting, no snapshots, clones, encryption, Fusion or sealed/system roles; add only when native compatibility established. No blank image labelled complete if missing mandatory metadata. Must pass native fsck_apfs and mount, including native subsequent read/write on disposable copy if advertised; third-party tool accepting it is insufficient. APFS docs alone may not specify all real writer invariants; maintain evidence register and fail closed when unresolved. Patents and license review before advanced writable release.

## Design

C3 sealed plan interface compatible conceptually with HFS+ via dmgez adapter, not common on-disk implementation. Validate logical tree names/collisions, metadata, data/resource/xattr streams, supported types and size. Assign deterministic container and volume UUIDs, object IDs, file IDs, transaction IDs and generation policy (explicit reproducibility, no random IDs on repeated deterministic profile); stable draft identity available for DMG background alias generation, then finalize generated payload. Volume roles and required flags based on evidence; don't set flags for unimplemented features. Use independent format-specific key comparators and directory hash rules. Plan physical blocks for all objects, data extents and allocation structures with checked sizes and a bounded convergence algorithm; no out-of-bounds or shared overlap without correct references. Metadata budget proportional to records/objects; optional bounded spool. Build filesystem tree (inode/drec/sibling/extent/xattr and required metadata records), extent reference trees/data stream records, volume and container object maps with correct address classes/XIDs. Build spaceman allocator data, free queues/bitmap/chunk structures, required reaper and checkpoint map/descriptor/data areas with coherent counts, valid empty structures where spec permits. Do not guess which structures can be omitted. Every reference resolves in the committed view, all live blocks allocated, all free/metadata counts consistent. Build container/volume superblocks, required checkpoint state and block-zero bootstrap, calculate object checksums over exact bytes, zero intentional padding. Qualify all algorithms with tiny native volumes first; then multi-level trees and large extents. Data and metadata placement must permit stable sector source; no journal needed for a clean new container but coherent checkpoint still required.

Seal interval map with exact byte length, known metadata bytes/source slices/zeros; read and stream sequentially or write to raw file without complete raw RAM buffer. Source data identity and mutation handling same C3/C4. Reproducible mode fixes canonical manifest and codec/profile inputs, reports if source metadata unavailable. If APFS read/format requirements imply random-access plan or scratch metadata, bounded scratch is acceptable; do not require direct sector streaming to delay reader. `write_to` raw sink and optional ReadAt plan; dmgez UDIF reader/writer filesystem-agnostic. For APFS DMG integration decide required GPT/volume layout by native fixture evidence, not assume partitionless HFS+ rules transfer to APFS. Native tools may choose different layouts; compare logical metadata and validity not exact Apple bytes. Preserve no signing/security state unless explicitly supported.

## Release gates

Fixture plan starts empty tiny volume, one file, nested dirs, symlink, hard link, small/large attrs and resource fork, Unicode variants, multi-GiB data, multi-level maps/trees, sparse range support only if qualified. Validate complete geometry, used/free allocation counters, object IDs/XIDs, checkpoint maps, checksums, no dangling pointers, exact metadata/data. Run fsck_apfs on disposable raw device/image, native read-only mount and read manifest, optionally native mutation on copy and recheck if claimed. Test independent reader; own round trip only supplemental. Signed synthetic .app bundles in dmgez integration compare actual mounted metadata/signature. Deterministic output and bounded payload memory; measure APFS metadata scaling. Block all write support if unexplained fsck errors or incomplete allocation accounting. No APFS requirement for dmgez v1.0.
