# APFS format verification

The [geometry harnesses](kani/geometry.rs) call the production NXSB size and geometry helpers. They check every unsigned 32-bit block-size value and cover all five admitted sizes from 4 KiB through 64 KiB. An independent 128-bit calculation checks admission and both byte endpoints across full-width 64-bit block counts, source lengths, range starts and range lengths. Coverage checks exercise both size admission outcomes, a geometry below the minimum, container-size overflow, admitted geometry, a nonempty range ending at the container boundary, an empty range at that boundary, and block-endpoint overflow.

The checkpoint-area harness calls the production NXSB decoder for both descriptor and data area layouts. It uses 4 KiB geometry with any admitted 64-bit container block count under a maximum-length source. It independently encodes arbitrary 64-bit addresses and 32-bit count, next, index and length fields. A 128-bit endpoint calculation verifies admission and decoded fields for the complete contiguous extent or the single block named by a fragment-tree locator. The seven cover checks include both field layouts, a fragment locator, a contiguous extent reaching the container boundary, a missing base, a zero count and an overflowing endpoint. Fragmented checkpoint areas remain outside the supported container profile. At `a44f5ea`, a separate test compared 4,032 typed ring ordinal queries with a distance-to-end calculation. It starts with the descriptor and data layouts decoded from an unchanged native checkpoint and varies the typed cursor fields. Each layout exercises an admitted wrap where the index plus ordinal exceeds `u32::MAX`. The matrix includes typed capacities beyond the 31-bit wire count. Its results apply to the public ring arithmetic. The clean workspace run passed all 228 tests, with transcript SHA-256 `452059bf831385e60ca4bdf6b65664c7bfbe865065a20da34419dc8797e7704f`. [Ring ordinal test](../tests/native.rs)

The [bootstrap tests](../../../container/apfs-container/tests/probe_extent.rs) start from a retained native APFS block. A malformed block size stops after the prefix. A count too large for byte addressing and an incorrect checksum stop after the single bounded bootstrap block. Adding an unknown required bit to the native incompatible feature mask also stops there, with an explicit unsupported-profile result.

The [checksum-window harness](kani/checksum.rs) checks the production word selection for every slice length from 0 through 40 bytes and arbitrary byte contents. An admitted slice must contain the complete 32-byte object header and end on a four-byte boundary. The selected window contains every byte in order after the stored eight-byte checksum. Coverage includes a truncated header, a header without payload, a partial payload word and two complete payload words.

The checksum integration tests check Fletcher-64 arithmetic with an independent `u128` weighted-sum oracle. Appending the two little-endian check words in logical order must zero both residues modulo `2³² − 1`. Each check word uses the nonzero representative of its residue. The unweighted sum fixes the sum of both check words. Subtracting that equation from the weighted sum, whose final weights are 2 and 1, determines the first check word. The tests verify all seven retained native objects and synthetic buffers at all five admitted block sizes from 4 KiB to 64 KiB. The synthetic buffers exercise uniform words and a distinct word at the first, middle, and last payload positions. The native objects are all 4 KiB. Run `bash check-native-windows.sh --asan` from this directory to repeat the native-window property test with AddressSanitizer on `nightly-2026-11-04`. It exercises all 7,119 aligned prefixes of the seven retained 4 KiB objects, from the complete 32-byte header through the full object. The production checksum must match the independent weighted-sum model, and the production type hint must match the wire header throughout. The sanitizer instruments target code and stops on a diagnostic. The separate `format-request-fuzz` profile provides revision-bound evidence for bounded checksum and range requests. Full A-V01 fuzz qualification remains open. [APFS release profiles](../../../../verification/README.md)

Run `bash fuzz/check-format-requests.sh --release-duration` on a dedicated runner to record at least two active hours for the scalar request target. Capture standard output and standard error together. The runner records the instrumented binary digest and the monotonic interval from libFuzzer initialization to completion. It uses twelve unchanged fixture objects across the five supported sizes. Full A-V01 fuzz qualification also requires wire-field and integrated bootstrap coverage.

The [object-header harness](kani/header.rs) encodes full-width symbolic values using the independent wire offsets for the checksum, object ID, transaction ID, type, and subtype. It checks the production field decoder and `Header::type_hint` for every prefix length through 32 bytes. The type hint begins succeeding at 28 bytes and the field decoder requires all 32 bytes. The public `Header::decode` additionally validates the checksum before returning the header.

Install Kani 0.68.0, run `cargo kani setup`, then run `bash check.sh` from this directory. From the repository root, run `cargo test --locked -p apfs-container --test probe_extent` for the native-derived checks.

On arm64 macOS, Kani 0.68.0 with CBMC 6.11.0 verified all five harnesses and reached all 47 cover properties. The seven bootstrap tests passed with Rust 1.99.1. The checksum integration tests passed in `cargo nextest run --locked --offline --workspace --no-default-features` with Rust 1.99.1 and Nextest 0.9.151. The run passed all 202 tests. All seven retained fixture hashes matched their ledgers.
