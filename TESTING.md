# APFS test and evidence plan

Source S12 plus native synthetic filesystems from licensed macOS (record exact OS build, tool syntax, size/block geometry, flags, volume roles, checkpoint IDs, manifest and digest). Use native newfs_apfs/diskutil to produce disposable raw data volumes, fsck_apfs read-only checker and read-only native mount for content/metadata oracle. Do not commit Apple OS images or proprietary content. No testing on host system volumes. Use candidate independent tools (`ferrosys`, `fstool`, `apfs`, `libfsapfs`, `apfs-fuse`) for supported overlaps; their agreement isn't sufficient proof. Pin commits/releases and licenses. Required oracle jobs fail if unavailable; no native test masquerades as passed on Linux. Use machine capability/evidence status per profile and actual OS version. Parser tests: invalid lengths, checksums/type, overflow, checkpoint ring wrap and partial commit, XID map versions/deletion, inconsistent object references, fixed/variable TOC, flags, tree depth/cycle, unsupported encrypted/sealed/Fusion. Native file oracle covers names, hash collisions, case variants, all metadata and data stream/fork lengths, sparse/shared extents, multi-volume, snapshots and compressed types as qualified. Fuzz each untrusted structure, object resolution, B-tree, filesystem records and decompression. Use budget assertions and read counters, no accidental full payload load. Fresh build tests geometry/coverage/no overlapping owner, exact block checksums, coherent allocator/reaper/free queues/checkpoint, native mount/fsck and read metadata; own roundtrip supplemental. Benchmarks memory/latency across large metadata trees and random reads; no absolute performance claims. Later mutation requires fault-injecting block device and invariant model at every commit persistence point, compare old/new valid states, native fsck after replay, snapshot/clone reclamation tests; no mutable release with unexplained failures. Credentialed/security tests isolated, authorized fixtures only; no bypass, secret leakage or brute force. `no_std` compile matrix separate from kernel qualification. Track requirement/test IDs in `docs/reference/`; all are planned until actual execution evidence.

## Verification integration

The local `VERIFICATION.md` and `verification/obligations.json` define mandatory profile-specific verification gates in addition to the original acceptance tests. Apply ecosystem standard EVS-1 (copy `shared/VERIFICATION.md` as `docs/architecture/ECOSYSTEM_VERIFICATION.md`). No required proof, model check, native test or critical fault gate can be substituted by coverage or a self-generated round trip. `cargo-nextest`, property tests, fuzz/corpus replay, coverage and deterministic architecture checks are required; formal methods activate at the milestones in the obligation registry.

## Kernel portability acceptance (A-PORT-01)
Execute all applicable A-PORT-01-T01..T04 cases from first engine release. Build each affected crate independently with defaults disabled and explicit kernel features on aarch64-unknown-none and x86_64-unknown-none; check target dependency features; run host harness with and without std using identical fixtures; verify hosted-only dependencies cannot enter the kernel profile. Record exact command and result. See EES-1 §3a. Full builds required at release; Charles integration is separately tested.
